01 · OVERVIEW

개요

학생 프로젝트 진행 현황을 관리하는 시스템에서 신규 데이터를 등록할 때 MySQL 오류가 발생했습니다. 애플리케이션 로직에서는 ID가 자동으로 생성될 것으로 예상했지만 실제 스키마는 그 가정과 일치하지 않았습니다.

02 · PROBLEM

문제 상황

학생 데이터를 INSERT하는 과정에서 id 컬럼에 기본값이 없다는 오류가 발생하며 등록이 실패했습니다.

Field 'id' doesn't have a default value
03 · OBSERVATION

관찰한 현상

  • 조회 기능은 동작했지만 신규 등록 요청만 실패했습니다.
  • 요청 데이터에는 학생 정보가 정상적으로 포함됐습니다.
  • INSERT 쿼리에서는 id 값을 직접 전달하지 않았습니다.
  • MySQL이 id 컬럼의 값을 요구하며 쿼리를 거부했습니다.
04 · HYPOTHESIS

처음 세운 가설

  • INSERT 쿼리의 컬럼 수와 값의 수가 다른지
  • 필수 컬럼을 누락했는지
  • Node.js에서 undefined 값이 전달됐는지
  • 테이블의 기본키 설정이 올바른지
05 · VERIFICATION

확인 과정

  1. 애플리케이션에서 실행되는 INSERT 쿼리를 확인했습니다.
  2. 전달되는 요청 데이터가 정상인지 확인했습니다.
  3. DESCRIBE 명령으로 실제 테이블 구조를 조회했습니다.
  4. id 컬럼의 Extra 값에 auto_increment가 없는 것을 확인했습니다.
DESCRIBE students;
06 · ROOT CAUSE

실제 원인

애플리케이션은 id가 자동으로 생성된다고 가정했지만 실제 테이블의 id 컬럼에는 AUTO_INCREMENT가 설정되어 있지 않았습니다. 코드의 가정과 데이터베이스 스키마가 일치하지 않은 것이 원인이었습니다.

07 · OPTIONS

검토한 해결 방법

  1. 애플리케이션에서 id 값을 직접 계산해 전달
  2. INSERT 쿼리마다 임시 기본값을 지정
  3. 현재 테이블의 기본키 구조를 수정
  4. 초기화 SQL과 INSERT 로직을 함께 정렬

애플리케이션에서 ID를 관리하면 동시 등록과 데이터 무결성 문제가 생길 수 있어 데이터베이스가 기본키를 생성하도록 정리했습니다.

08 · ACTION

선택한 조치

id 컬럼에 PRIMARY KEY와 AUTO_INCREMENT를 설정하고 INSERT 쿼리에서는 id 값을 직접 전달하지 않도록 정리했습니다.

수정 전
id INT NOT NULL
수정 후
id INT NOT NULL
  AUTO_INCREMENT
  PRIMARY KEY

현재 데이터베이스만 수정하는 데 그치지 않고 새 환경에서도 같은 문제가 발생하지 않도록 테이블 생성 SQL에도 변경 내용을 반영했습니다.

09 · RESULT

결과

  • 신규 데이터가 정상적으로 등록됐습니다.
  • ID가 데이터베이스에서 자동으로 생성됐습니다.
  • 실행 환경마다 테이블 구조가 달라질 가능성을 줄였습니다.
검증 결과: INSERT 요청이 정상 완료되고 생성된 ID를 이후 조회 흐름에서 사용할 수 있었습니다.
10 · PREVENTION

재발 방지

  • 데이터베이스 초기화 SQL을 저장소에서 관리합니다.
  • 애플리케이션 코드와 실제 스키마를 함께 확인합니다.
  • 배포 시 사용하는 테이블 생성 스크립트를 동일하게 유지합니다.
11 · NEXT

남은 개선점

스키마 변경 이력이 늘어나면 초기화 SQL만으로는 변경 과정을 추적하기 어렵습니다. 이후에는 마이그레이션 파일과 적용 순서를 명시해 기존 환경과 신규 환경을 같은 구조로 유지할 수 있습니다.

12 · LEARNING

배운 점

데이터베이스 오류를 애플리케이션 코드만 보고 판단해서는 안 됐습니다. 코드가 전제하는 데이터 구조와 실제 데이터베이스에 적용된 구조가 일치하는지 함께 검증해야 했습니다.
