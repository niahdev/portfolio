INCIDENT 032026.08RKE2 LabInfrastructure · Networking

Kubernetes 클러스터에
IngressClass가 존재하지 않은 문제

Ingress YAML만 수정하지 않고 요청을 처리할 Controller와 클러스터 구성을 먼저 확인하며 원인 범위를 좁힌 기록입니다.

01 · OVERVIEW

개요

RKE2 기반 Kubernetes 클러스터에서 서비스를 Ingress로 외부에 노출하는 테스트를 진행했습니다. Ingress 리소스를 작성하기 전에 클러스터 구성을 확인했지만 사용할 수 있는 IngressClass가 존재하지 않았습니다.

02 · PROBLEM

문제 상황

Ingress를 구성하기 위해 현재 등록된 IngressClass를 조회했으나 리소스가 존재하지 않는다는 결과가 반환됐습니다.

$ kubectl get ingressclass
No resources found
03 · OBSERVATION

관찰한 현상

  • IngressClass 목록이 비어 있었습니다.
  • Ingress에서 지정할 class 이름을 확인할 수 없었습니다.
  • Ingress 리소스만 작성해도 실제 요청을 처리할 주체가 불분명했습니다.
  • 애플리케이션 리소스와 클러스터 애드온 구성을 분리해 봐야 했습니다.
04 · HYPOTHESIS

처음 세운 가설

  • Service 또는 Pod가 Ready 상태가 아닌지
  • Ingress YAML의 apiVersion이 올바르지 않은지
  • ingressClassName 지정이 누락됐는지
  • Ingress Controller가 설치되지 않았는지
  • Controller는 있지만 IngressClass를 등록하지 않았는지
05 · VERIFICATION

확인 과정

Pod와 Service가 정상이어도 Ingress 요청을 처리할 Controller가 없다면 Ingress 리소스만으로 외부 연결이 만들어지지 않습니다. 먼저 클러스터 전역의 Controller 후보와 RKE2 애드온 구성을 확인하는 순서로 범위를 좁혔습니다.

kubectl get pods -n kube-system
kubectl get daemonset -A
kubectl get deployment -A
kubectl get helmchart -A
06 · ROOT CAUSE RANGE

실제 원인 범위

아직 원인을 확정한 상태는 아닙니다. 현재 클러스터에는 사용할 수 있는 Ingress Controller가 설치되지 않았거나 Controller가 IngressClass를 등록하지 않은 상태일 가능성으로 범위를 좁혔습니다.

확정된 사실: kubectl get ingressclass 결과가 비어 있음. 확인 중인 범위: Controller 설치·등록 상태.
07 · OPTIONS

검토할 해결 방법

  1. RKE2 기본 Ingress Controller가 비활성화됐는지 확인
  2. 기존 HelmChart 또는 Controller 배포 상태 복구
  3. 환경에 맞는 Ingress Controller 신규 설치
  4. Controller가 생성한 IngressClass 이름을 명시해 테스트
08 · ACTION

선택한 다음 조치

  1. kube-system 네임스페이스의 Controller Pod 확인
  2. RKE2의 기본 Ingress 구성 여부 확인
  3. 설치된 HelmChart 또는 DaemonSet 확인
  4. Controller 설치 후 IngressClass 생성 여부 확인
  5. ingressClassName을 지정한 테스트 Ingress 적용
  6. 도메인 또는 hosts 설정으로 외부 접근 검증
09 · CURRENT RESULT

현재 결과

Ingress가 동작하지 않는 원인을 YAML 문법만의 문제로 보지 않고 클러스터의 Controller 구성으로 조사 범위를 옮겼습니다. 해결 완료가 아니므로 상태는 Investigating으로 유지합니다.

현재 판단: 애플리케이션 리소스보다 Ingress Controller와 IngressClass 등록 상태를 먼저 검증해야 합니다.
10 · PREVENTION

재발 방지

해결 후에는 사용한 Controller, IngressClass 이름, 설치 방식과 검증 명령을 클러스터 구성 문서에 남기고 새 환경 점검 항목에 포함할 예정입니다.

11 · NEXT

남은 개선점

  • 적용한 Controller와 IngressClass 이름 기록
  • 테스트 Service와 외부 접근 방법 기록
  • 정상 응답 화면과 리소스 상태 증거 추가
  • Controller 재시작과 노드 변경 상황 검증
12 · LEARNING

배운 점

Ingress가 동작하지 않는다고 처음부터 YAML 문법만 수정하지 않았습니다. 애플리케이션 리소스와 클러스터 리소스를 분리하고 요청을 실제로 처리할 Controller가 존재하는지부터 확인해야 했습니다.
