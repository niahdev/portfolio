INCIDENT 032026.07OVHcloud VPSServer Access · Linux

OVH VPS의
SSH 개인키 인증 복구

기존 로컬 개인키 인증이 거부돼 배포 서버에 접근할 수 없었던 상황에서, OVH 제공 콘솔을 비상 경로로 사용해 공개키를 다시 등록한 사례입니다.

01 · OVERVIEW

개요

로컬 PC에서 기존에 사용하던 SSH 개인키로 OVH VPS에 접속하려 했지만 공개키 인증이 더 이상 통과하지 않았습니다. 서비스는 동작 중이었지만 운영과 배포를 위한 서버 접근이 중단된 상태였습니다.

02 · PROBLEM

문제

여러 계정과 로컬 키를 명시해 접속을 확인했지만 서버가 공개키 인증을 거부했습니다.

Permission denied (publickey)
03 · OBSERVATION

관찰

  • 초기에는 SSH 22번 포트까지 연결됐지만 키 인증이 실패했습니다.
  • 별도 배포 키도 대상 계정에서 승인되지 않았습니다.
  • 확인 과정 중에는 22번 포트 연결 타임아웃도 발생했습니다.
  • 일반 SSH 경로만으로는 서버 안의 키 등록 상태를 수정할 수 없었습니다.
04 · CAUSE RANGE

원인 범위

서버에 등록된 공개키와 로컬 개인키의 대응 상태, 대상 계정의 authorized_keys, SSH 접근 제어 상태로 범위를 좁혔습니다. 당시 기록만으로 단일 원인을 확정하지는 않았습니다.

확정된 사실: 기존 로컬 키 인증이 거부됐고, 서버 측 공개키를 재등록한 뒤 동일 계정의 접속이 복구됐습니다.
05 · RECOVERY

복구

  1. OVH에서 제공하는 웹 콘솔/CMD 환경으로 서버에 접속했습니다.
  2. 기존 SSH 키 인증 상태를 초기화했습니다.
  3. 로컬 개인키에 대응하는 공개키를 서버 계정에 다시 등록했습니다.
  4. 일반 SSH 접속 경로로 돌아와 인증을 재확인했습니다.
콘솔에서 사용자가 직접 실행한 세부 명령은 세션에 남아 있지 않아 임의로 재구성하지 않았습니다.
06 · VERIFICATION

검증

  • ubuntu 계정으로 SSH 접속 성공
  • 서버 호스트명과 Linux 운영체제 확인
  • /home/ubuntu 쓰기 가능 확인
  • 이후 파일 업로드와 Nginx·서비스 배포 진행
07 · RESULT

결과

운영 서버의 관리 접근을 복구했고, 중단됐던 배포 작업을 이어갈 수 있었습니다.

검증 결과: SSH 로그인과 홈 디렉터리 쓰기가 정상 동작하고 이후 실제 서비스 배포까지 완료했습니다.
08 · PREVENTION

재발 대비

  • OVH 웹 콘솔 같은 별도 관리 경로를 비상 접근 수단으로 유지합니다.
  • 서버 계정과 공개키·로컬 키 파일의 대응 관계를 기록합니다.
  • 키 지문을 비교해 잘못된 키 사용 여부를 빠르게 확인합니다.
  • 키 인증 실패와 네트워크·방화벽 차단을 분리해 진단합니다.
09 · LEARNING

배운 점

SSH는 서버 운영의 단일 진입점이 될 수 있으므로, 키 인증이 끊겼을 때 사용할 공급자 콘솔과 복구 절차를 미리 확보해야 합니다. 접속 실패도 인증 문제와 네트워크 문제를 구분해야 원인을 빠르게 좁힐 수 있습니다.
