INCIDENT 02 · ER-Dodge

외부 API 장애가
분석 기능으로 전파된 문제

외부 데이터의 최신성과 서비스 가용성을 분리하고 마지막 정상 데이터로 기능을 유지하도록 바꾼 기록입니다.

External APICacheFallbackValidation
01 · PROBLEM

기준 데이터 API가 실패하면 사용자 분석 화면도 중단됐습니다.

ER-Dodge는 사용자 전적을 외부 기준 데이터와 비교합니다. 기준 데이터 제공처의 응답이 늦거나 실패한 경우 분석에 필요한 값이 없어 전체 요청이 오류로 끝났습니다.

02 · OBSERVATION

사용자 전적 조회는 정상이어도 기준 데이터 단계에서 실패했습니다.

데이터 수집 단계를 분리해 응답 코드, 스키마 검증 결과, 마지막 정상 갱신 시각을 확인했습니다. 장애 범위가 전체 서비스가 아니라 특정 외부 데이터 제공처임을 구분했습니다.

확인한 신호: 외부 응답 상태 · 필수 필드 존재 여부 · 캐시 생성 시각 · 분석 단계 진입 여부
03 · HYPOTHESIS

최신 데이터를 반드시 실시간으로 받아야 한다는 가정을 다시 봤습니다.

기준 통계는 매 요청마다 최신일 필요가 없고 마지막 정상 데이터로도 분석을 제공할 수 있습니다. 최신성과 가용성을 같은 조건으로 묶은 것이 문제라고 판단했습니다.

04 · ROOT CAUSE

분석 로직이 실시간 외부 응답에 직접 의존했습니다.

수집 실패와 분석 실패가 분리되지 않았고 대체할 데이터 소스도 없었습니다. 외부 API의 일시 오류가 내부 기능 전체의 오류가 되는 결합 구조였습니다.

05 · FIX

자동 갱신, 마지막 정상 캐시, 번들 데이터의 3단계 구조로 변경했습니다.

정상 응답만 검증 후 캐시에 저장합니다. 갱신에 실패하면 마지막 정상 캐시를 사용하고, 초기 상태처럼 캐시가 없으면 함께 배포한 기본 데이터로 최소 분석을 제공합니다.

  • 외부 응답 스키마 검증 후 정상 데이터만 저장
  • 갱신 실패 시 마지막 정상 캐시 사용
  • 캐시가 없으면 번들 데이터로 최소 기능 제공
06 · RESULT

외부 제공처의 일시 장애와 분석 기능의 가용성을 분리했습니다.

기준 데이터 갱신이 실패해도 유효한 이전 데이터가 있으면 분석 흐름이 계속됩니다. 화면 중단 대신 데이터 갱신 시점의 차이로 장애 범위를 줄였습니다.

검증 결과: 외부 API 실패 조건에서도 캐시 또는 번들 데이터로 분석 응답이 완료됨
07 · PREVENTION

외부 데이터는 검증·저장·대체 경로를 함께 둡니다.

갱신 성공 여부와 사용 중인 데이터 출처를 로그로 구분하고, 잘못된 응답이 정상 캐시를 덮어쓰지 않도록 검증 이후에만 교체합니다.
